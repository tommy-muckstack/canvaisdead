# Text lists

Date: 2026-10-16. Native verification pending.

The List toolbar button previously displayed an unsupported toast. It now opens a keyboard-operable menu with No list, Bulleted list and Numbered list. Formatting changes the selected text element, preserves its source text and text anchor, respects locks, and participates in one-step history. Reapplying the current style is a no-op.

A shared text layout reserves a hanging gutter wide enough for the widest numbered marker, wraps continuation lines within the remaining width and emits one marker for each explicit paragraph, including blank items. Markers are separate from editable text, so typing and plain-text indices do not include synthetic prefixes. The editing overlay refreshes markers as paragraphs are added/removed; native textarea input, caret and IME behavior remain in use. Canvas/selection, page/layer/project/presentation previews, SVG and PNG/JPG/PDF raster rendering all consume the same layout. Text without list formatting retains the preceding exact renderer output.

Lists remain local: autosave/streaming backups use record version 8 when list metadata exists, and ordinary libraries retain version 7. Portable legacy JSON with lists uses version 8 (version 7 is reserved for record encoding); older JSON versions reject list metadata. Element clipboard version 5 maps to backup validation version 8. Rich clipboard preserves structure, while plain text includes readable markers. Existing backup formats remain supported. Unsupported future-version tests now use the next unsupported versions; no validation assertion was removed.

The [official text-formatting guide](https://www.canva.com/en_au/help/format-text/) documents bullet and numbered options on desktop and mobile. Its section heading also mentions checklists without describing their behavior. Direct interactive reference comparison remains unavailable, so this implementation does not establish exact menu, marker, spacing or editing parity. Mixed per-paragraph styles, nested lists/indent controls, soft returns, empty-item list exit, start/restart numbering, checklists and formatted external-list paste remain required work, alongside broader rich-text editing. Formatting currently applies to the whole selected text element. No subscription or paid gate is added.

Local lint/typecheck/build and 416 unit tests pass. Nine new units cover hanging/multi-digit gutters, paragraph numbering, grapheme preservation, tracking, rotated anchor/resize geometry, locks/no-ops/history, SVG/raster marker coordinates and decoration, both backup encodings, clipboard and malformed/old-version metadata. The existing exact SVG golden exposed a floating-point multiplication-order change; restoring the previous order preserves its output.

Eight new native cases at 1440px/390px will verify menu keyboard/focus/bounds; formatting and no-op history; live editing/caret and reload; actual SVG/PNG marker exports; native rich/plain clipboard; downloaded backup/import round trips; and locked controls. All existing browser cases remain selected with no new exclusions. Baseline captures restore the preceding Editor/TextEditor/menu/CSS consumers and exercise the old unsupported control with unformatted text; the new list renderer and codec are not exercised in that baseline. Before/after PNGs, computed metrics and accessibility snapshots will be retained after terminal results.
