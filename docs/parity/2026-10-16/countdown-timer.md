# Countdown timer

Date: 2026-10-16. Parent main: `1b22193d927aff00d8a0c061aa3dba88f69127fd`. Status: **differs / P1**, pending native verification and direct original comparison.

The [official timer guide](https://www.canva.com/help/set-timer/) describes a five-minute default, editable time, play/reset, adding one minute, minimized status, five music choices, volume and start/ten-second/end cues. It also describes number shortcuts in presentations and access from presenter/audience windows. The reference says desktop only; the clone also makes these controls usable at 390px. No original sounds, tracks, screenshots or assets were copied.

The editor's static Timer label becomes a functional countdown control. A shared component supplies the same controls in standard/autoplay, presenter and audience views. Start/pause, reset, +1 minute and duration validation operate independently of the artwork/history. Time comes from a saved deadline, so background throttling and sleep do not accumulate interval drift. Pause keeps fractional remaining milliseconds; display rounds upward to whole seconds. Reset returns to the configured duration. Adding a minute extends the current countdown without changing the reset duration; adding after completion leaves a paused minute. Starting a completed countdown reuses the configured duration. Duration supports 0:01–1439:59; exact original limits and reset/add semantics still need direct comparison.

Opening focuses the heading; Escape minimizes and restores the trigger, without exiting a presentation. Outside clicks minimize while preserving the clicked control's focus. Invalid time never commits; Escape discards it. Number keys 1–9 open/reset a presentation countdown, including while its heading is focused, and never replace typed input in fields. Time remaining has timer semantics with live announcements disabled; completion is announced once. The paused minimized value pulses, respecting reduced-motion preferences. The panel is positioned within the viewport and remains scrollable.

Timer settings use a separate versioned localStorage key scoped by owner and design. They contain only timing/music/volume settings; no design content or notes. Only explicit controls write, not ticks. Same-origin editor/presenter/audience windows react to storage events, focus and visibility. Actions first read other-window settings. Concurrent controls use last-write-wins; they are not collaborative transactions. Failed writes retain the current window's settings for retry, and corrupt bytes are not overwritten on read. Timers are not included in artwork exports, undo history or design backups. No cloud storage, network service, dependency, payment change or secret is added.

All five music choices use original oscillator patterns, with generated start, ten-second and completion cues. Volume zero silences the master output. Sound starts after user interaction and plays only in the focused visible window, avoiding duplicate playback from the presenter and audience. Pausing or changing the music stops prior voices; unmounting closes the AudioContext and interval. Browsers that refuse audio display a message while the countdown keeps working. Background audio suspension and exact cue timing depend on browser visibility/audio policy. These patterns are free equivalents, not copied recordings.

Six unit cases cover deadlines/sleep, pause/resume/reset, add-minute behavior/limits, parsing, invalid settings, local separation, cross-window reads, no tick writes, corrupt storage, failed-write recovery and audio cleanup. Twelve native cases across 1440×900 and 390×844 exercise actual UI timing, reload, keyboard/focus, settings, presenter/audience synchronization, separate designs, error/retry and real Web Audio analyser samples/zero volume. Before/after captures cover editor and presentation footer controls; new panel and paused views have no working baseline counterpart. Native results and retained captures follow terminal CI. Local lint, typecheck, production build and 448 unit tests pass. The inventory has 260 cases in disjoint general (58), storage (32) and focused (170) partitions; two existing touch-only skips remain.

Remaining requirements: direct logged-in original screenshots/computed styles and exact control placement, original time limits and interaction semantics, original-equivalent audio polish, More-menu entry, automatic popup behavior in other windows, physical-device and cross-browser testing. Cross-device/collaborator timers require the broader collaboration feature, still unfinished; no paid-only waiver. The separate elapsed presenter clock is unchanged. Full parity is not established.

Initial native run [38981132416](https://github.com/tommy-muckstack/canvaisdead/actions/runs/38981132416) passed 448 units, 256 browser cases and both baseline capture flows, with two existing skips and two failures. Both failures exposed the same production cancellation bug: restoring trigger focus on Escape synchronously fired the duration field's blur handler before the cleared draft rendered, committing the value intended to be discarded. A synchronous cancellation ref now suppresses that blur commit and resets on the next field focus; the existing failing assertions are retained. Review also found presentation captures racing route navigation; capture now awaits the presentation root before measuring. The initial captures are not used as final presentation evidence. A fallback More icon was replaced with the intended original minus path for Minimize. Final native verification follows these changes.
