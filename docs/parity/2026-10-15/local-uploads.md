# Local uploads library — 2026-10-15

## Compared

The official [upload workflow](https://www.canva.com/help/upload-media/) and [add-images guide](https://www.canva.com/help/add-images/) describe importing files into Uploads and choosing/dragging them into a design. The [manage-uploads guide](https://www.canva.com/en_in/help/manage-uploads/) documents original downloads, item menus, bulk selection, Trash and recovery. [Format requirements](https://www.canva.com/help/upload-formats-requirements/) establish a broader media/format scope and published image limits. These are documentation-level comparisons; browser captures and exact behavior remain unverified.

Previously, one chosen image was immediately placed in the design after resizing its longest side to 1,400 pixels and converting most formats to JPEG. There was no reusable upload library, original-file download, batch import, search, file management or drop target. Clipboard raster imports used the same lossy conversion.

## Change

- Keep original raster file bytes in an IndexedDB library scoped to the current account and browser origin. Store separate PNG thumbnails of at most 240 pixels on the longer side. PNG, JPEG, WebP, GIF and AVIF are identified by binary headers, then decoded by the browser; filenames/MIME claims alone are not trusted. SVG/HEIC, documents, video and audio remain unsupported. The current cap is 50 MiB per file and 250 million decoded pixels, subject to actual browser decoding/memory limits. Animation timing is not implemented.
- Select multiple files or drop them on Uploads. Files enter the library without automatically becoming canvas elements. Actual queued/reading/saving states, cancellation before the commit phase, per-file failure, dismiss and retry replace silent failures. Imports run sequentially and survive client-side editor navigation in browser memory. Failed saves retain the prepared original and retry the same ID; an invalid file does not stop the rest of the queue.
- Search names/file types, browse real thumbnails and select one or several images. Image library items can be dragged onto the desktop page; external file drops on the page import and then insert successful images together. Insertion retains original bytes, uses independent image IDs and one history step, and appends to the latest committed artwork. Accepted drops queue while an earlier original is being read, so a busy insertion does not silently discard the next drop. A changed page/document, active edit/drag/crop/grid view, removed upload or changed drop-page size prevents a stale async insert. Images remain in the library for another attempt.
- Reuse uploads across designs in the same local account. More/right-click/Shift+F10 actions download original bytes, rename, select items and move to Trash. Bulk Trash, restore and confirmed permanent deletion are available. Trash expires after 30 days according to the device clock while the library is loaded/refreshed. Deleting a library original never removes embedded copies in designs.
- Native modal dialogs, labeled controls, keyboard tabs, menu navigation, focus return, local status/error states and mobile touch targets use the existing editor conventions. Video/Audio tabs state current availability. Thumbnail object URLs are revoked when replaced/unmounted; original download URLs are released after starting a local download.
- Each file-management write re-reads current records in a single IndexedDB transaction. Completion is acknowledged on the transaction's complete event, consistent with [IndexedDB's commit contract](https://developer.mozilla.org/en-US/docs/Web/API/IDBTransaction/complete_event). Exact Trash timestamps protect restore/delete from stale confirmation. Failed reads preserve existing records; future record/database versions are not overwritten. BroadcastChannel and focus/periodic refresh update other open editors; blocked notifications do not change file storage.
- Clipboard raster insertion now preserves original bytes too and accepts the same five embedded formats already supported by portable backups. No design model or portable version change is needed.

## Verification

Lint, typecheck, production build and all 329 unit tests across 27 files pass with the existing dependency overlay. Twelve new unit cases cover binary type detection, byte-for-byte encoding across chunk boundaries, size/abort validation, metadata versions/account names, real search, Trash generations/retention, insertion/backup/clipboard/SVG/history, serialized imports, commit acknowledgement, quota retry, cancellation, stale reads and failed file actions.

The queue tests use an asynchronous in-memory repository. **They do not prove IndexedDB runtime behavior, decoding, DOM events, Blob URL lifecycle, transaction durability or actual pixels.** No browser automation tool is exposed, and the previously observed browser launch failures remain. Playwright discovers 124 scenarios across 22 files, including fourteen new Uploads instances. They cover original downloads/reload/cross-design reuse, file management, an aborted quota transaction/retry, file drop events, delayed page changes, queued drops with separate history, original-image crop/flip/export and native desktop thumbnail dragging. The mobile native-drag instance explicitly skips. None of these browser cases ran; `uploads-library.png` is only a planned filename, not screenshot evidence.

## Capacity and remaining work

**Original-file capacity is ahead of design persistence.** Designs still store embedded base64 sources in localStorage. A library import can succeed while placing that same file exceeds the browser's much smaller design-storage quota. The existing unsaved notice retains edits in memory, but this is not storage parity. The backup importer still rejects files over 50 MiB; for example, a 50 MiB original alone becomes roughly 66.7 MiB when base64-encoded, before document metadata. Original files remain downloadable from Uploads, but that does not recover a lost layout. Upgrade design persistence and portable recovery for large media before treating this path as ready for broad use. Do not reduce image quality silently to hide that gap.

Unplaced originals and Trash are not part of design backups or guest-to-account handoff. Originals are not shared between origins/devices; clearing or evicting browser storage can remove them. Keep source files. A complete media backup/handoff path and larger-library pagination/performance checks remain required work.
