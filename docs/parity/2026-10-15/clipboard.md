# Clipboard and canvas context menu — 2026-10-15

## Compared

The official [text guide](https://www.canva.com/help/add-and-edit-text/) documents Ctrl/Cmd+C and Ctrl/Cmd+V for selected text boxes. The [element guide](https://www.canva.com/en_au/help/add-elements/) documents right-click duplication, and the [sticky-note guide](https://www.canva.com/help/using-sticky-notes/) documents floating More → Copy and using copied text externally. These establish workflows, not measured placement or a complete current context-menu catalog. The clone previously implemented duplication but no clipboard integration or canvas context menu.

The [browser Clipboard API documentation](https://developer.mozilla.org/en-US/docs/Web/API/Clipboard_API) describes native clipboard events, secure-context access, activation and browser-specific permissions. This change uses native events for keyboard operations and standard text/HTML ClipboardItems for menu operations; it does not request clipboard access in the background.

## Implemented

- Native copy/cut/paste preserves ordinary input, textarea, contenteditable, dialog, page-list and active text-editing behavior. Copying an existing native DOM text selection remains native. Canvas pointer selection clears stale DOM text ranges, and artwork SVG disables browser text selection so element selection is independent.
- A versioned selection payload carries selected geometry/styles, embedded raster media, nested membership, canvas size and opaque source design/page IDs. It excludes names, notes, account information, unrelated elements and unknown fields. Partial group selections detach from incomplete ancestors. Standard HTML carries the encoded data; plain text stays readable outside the editor. Native copy also provides a custom MIME representation where supported.
- Paste validates the whole payload, including portable media/paint, dimensions and group structure. Invalid/unsupported versions and remote image URLs are rejected. Foreign HTML is never mounted or parsed into a DOM; ordinary external text is inserted literally. Pasted groups/elements receive independent IDs and preserve paint order. Destination geometry is unchanged apart from translation.
- Equal-sized pages retain source coordinates. Same-page/repeated pastes add 24-pixel offsets; different canvas sizes center the artwork without scaling. Right-click Paste centers at the pointer. These placement choices require direct reference comparison.
- Plain text creates a text box with line breaks and Unicode preserved. Raster clipboard files use the existing local image conversion, up to 1,400 pixels on the longest side. Multiple files form one history operation, and alternate MIME encodings of one clipboard image are not inserted twice. SVG, remote image HTML, video and other unsupported content are not fetched or imported.
- Cut requires the selected units to be unlocked and waits for the entire clipboard write. Denied/unsupported access keeps originals. Late completion after a changed selection, design or page copies without cutting. Paste similarly refuses a stale destination after asynchronous reads/decodes. Cut and paste are each one undo step and use the existing local autosave/recovery behavior. No stale in-memory clipboard fallback can replace newly copied external content.
- The shared menu opens through right-click, ContextMenu/Shift+F10 and More buttons for single/multiple selections or the blank canvas. Actions include clipboard, duplicate/delete, group/ungroup, locks, four stacking operations and selection. Native menu roles, disabled states, arrow/Home/End navigation, Escape/Tab/outside dismissal, focus return and viewport clamping are implemented.
- Files and decoded images stay in local browser storage/downloads; explicit copy uses the device’s system clipboard. No network request, dependency, service, auth provider, payment gate, telemetry or credential change is added. Clipboard artwork currently permits 50 MB and plain text 100,000 characters per paste.
